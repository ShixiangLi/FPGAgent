# 已保存数据的模型驱动分析

本轮在用户恢复的代码版本上修改，保留现有开发流程。新增 `analyze` 入口，复用 DeepSeek 客户端、增量编辑器和 Python 执行器，处理已有 CSV/VCD 的分析与验收问题。没有把呼吸灯的峰值算法、周期阈值或修复方法写进框架。

## 职责边界

DeepSeek 选择读取、修改、执行、提问、停止或提交结论；分析算法和项目脚本由 DeepSeek 生成。框架执行选定动作，保存原始结果、工作检查点和来源，并反馈路径、格式、超时、缺失产物等基础问题。

工具结果中的 `passed` 表示进程执行和声明产物检查通过；模型的 `assessment.approved` 表示模型对当前分析证据的结论。二者独立保存。退出码 0 不会自动产生功能验收结论；修改脚本后，旧脚本的成功结果不能用于新脚本的验收。

现有完整开发流程仍保留仿真、构建、审查、下载等阶段及原来的基础执行门槛。本次没有将整个框架重写为任意工具调用系统，也没有移除版本一致性、用户确认、超时等机制。

## 启动和交互

从任务中明确选择工程候选、输入数据和候选内已有的分析脚本。以下命令创建一个新的分析会话，会实际调用配置中的模型并执行其选择的 Python 分析：

```powershell
.\.venv\Scripts\python.exe main.py analyze 20261031-103023-eb127f `
  --candidate revisions/20261031-111756-a4a6/candidate-0.json `
  --source runs/program-1793417003855404900/hardware_samples.csv `
  --script scripts/analyze_hw.py `
  --request "分析这份真实VIO采样，检查原需求的亮度、互补关系、周期和采样时长，输出曲线和报告。自行决定如何修复指定分析脚本并执行；不修改RTL和原始数据，不降低原要求，不重新下载。说明未验证事项，证据不足可以提问或停止。"
```

默认在模型提问时等待终端回答，空行继续等待，`/pause` 保存退出。使用 `--non-interactive` 则在需要回答时保存退出。暂停、中断或问题待答后，用终端显示的分析会话 ID 恢复：

```powershell
.\.venv\Scripts\python.exe main.py analyze <任务编号> --resume <分析会话ID>
.\.venv\Scripts\python.exe main.py analyze <任务编号> --resume <分析会话ID> --answer "对待澄清问题的回答"
```

恢复沿用已保存的需求、数据和基线，不同时传入新的 `--candidate/--source/--script/--request`。需要扩大分析范围或替换数据时创建新会话。已结束会话只返回记录，不重复执行。

退出码：0 表示模型批准本轮分析；2 表示等待回答或达到动作预算等暂停状态；1 表示失败或模型未批准。默认每次运行最多 12 个分析调度动作；增量编辑器沿用自己的检查点与预算。达到预算保存现场，不自动认定模型无法完成。

## 文件与信息流

```text
用户选定候选、数据和范围
  → 冻结候选与输入副本
  → DeepSeek 选择动作
      read_files → 按窗口读取真实文件
      edit       → DeepSeek 增量编辑指定分析脚本
      execute    → Python 实际执行 → 返回结果及证据路径
      clarify    → 保存问题 → 用户回答 → 恢复
      finish/stop→ 保存模型结论及未覆盖事项
```

产物位于 `workspace/<任务编号>/analysis/<分析会话ID>/`：

| 路径 | 内容 |
| --- | --- |
| `baseline.json`、`input.csv` 或 `input.vcd` | 所选基线和输入副本 |
| `state.json`、`report.md` | 状态、来源哈希、模型决策、执行结果和范围受限的结论 |
| `project/` | 候选工程副本，编辑器仅允许修改指定分析脚本 |
| `editing/`、`working.md` | 增量编辑检查点，支持中断恢复 |
| `llm_calls.jsonl`、`events.jsonl` | 模型调用记录和过程事件 |
| `runs/<执行ID>/` | 实际命令、退出码、完整日志、输入副本和报告/图片 |
| `artifacts/<执行ID>/` | 执行通过后的产物副本 |

读取窗口和报告摘录有大小上限，完整文件保留在记录的路径中。模型维护累计摘要，并可继续读取其他窗口。选定脚本的执行前哈希记录在会话结果中；输入与其余基线文件的哈希用于检查证据一致性。

独立工作目录和哈希检查不是操作系统安全沙箱。生成的 Python 在当前账号权限下运行，仍应遵守任务范围；本轮通过前后哈希核对确认原工程、候选、CSV 和任务状态均未改变。

## 同时修正的共用机制

- 原始异常保留阶段、类型、命令、退出码和日志；硬件失败不再自动用模型诊断覆盖错误。显式 `diagnose` 将模型解释单独保存。
- 修复编辑器收到真实输入预览、日志和报告的可读路径；读取反馈明确列出可用与不可用文件。
- 编辑器收到统一执行接口，可交回执行验证；每个编辑动作最多修改 3 个文件，不再把累计草稿也误限制为 3 个文件。
- 复审收到上次阻塞项，模型依据新证据判断是否解决。
- VCD 超过预览事件预算时仍扫描完整数据并统计事件，图片明确标注截取范围；不再仅因超过 500000 个事件而中止绘图。完整波形仍由项目脚本按需求分析。

## 2026-10-31 实际验证

配置沿用 `deepseek-flash`、开启思考、`high`、输出上限 `32768`。会话 `12973b1118c9` 使用历史真实上板采样，未重新仿真、构建或下载。
