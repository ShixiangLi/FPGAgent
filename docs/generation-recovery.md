# 模型小步生成与阶段续接

当前版本把需求、方案、审查和资料研究的多轮生成集中到 `fpga_agent/model_steps.py`。文件编辑仍复用原增量编辑器；独立采样分析保留原动作循环。它们使用相同的暂停信息结构，避免给每个阶段分别增加一套重试方案。

## 两种限制

上下文过长和单次输出预算耗尽是两个问题。按需读取、摘要和草案可以减少默认输入；它们无法找回服务端尚未输出的思考。模型仍可能用完当前预算，框架负责保留现场和恢复路径，不承诺每次请求都能生成有效正文。

当前模型、思考强度和输出预算均继续来自 `config.json`。本次没有自动更换模型、降低思考强度或增大预算。

## 模型动作与职责

需求、规划、审查可分轮返回：

```json
{
  "action": "checkpoint",
  "summary": "已完成和待完成的公开工作摘要",
  "next_step": "下一轮一个小步骤",
  "updates": {"design": "这一部分方案"},
  "append": {"development_tasks": [{"id": "example", "goal": "示例"}]}
}
```

示例仅展示分步更新形式，实际最终任务还需满足完整执行接口。

- `updates` 递归合并对象，其他值替换；`append` 向顶层数组追加模型生成的项。
- 草案放在检查点中；较大草案通过 `draft.json` 索引读取，默认上下文显示字段索引。
- `read_files` 按索引读取文件，每次最多6个文件、每个窗口1..8000字节。
- 模型返回 `submit` 时，框架把草案原样送入现有接口检查。也兼容模型直接返回完整结果。
- 审查的 `approved`、阻塞项和覆盖说明均由模型给出。框架只检查数据结构、执行前置条件和证据版本一致性。
- 输出截断时不应用残缺正文。先保存草案和原始调用元数据，让模型用一个短检查点选择更小步骤。

文件编辑器仍使用片段修改与 `deliver`，`offset/limit` 沿用字符单位；它的任务边界和澄清续接规则保持有效。

## 暂停与恢复

新暂停状态为 `model_paused`，CLI退出码2。`state.json`、`progress.md`、任务报告和终端输出包含 `model_pause`：阶段、检查点路径、原因、实际模型配置和可选操作。

公共阶段默认每批最多16个模型动作；同一批两次输出预算耗尽后暂停。编辑器保留已有的小步、无进展和截断上限。独立分析决策超限后直接保存该分析会话，等待续接。原始日志和模型完整返回继续保留，不拼接截断JSON。

继续完整开发任务：

```powershell
.\.venv\Scripts\python.exe main.py run --resume <任务编号> --continue
```

需求阶段即使尚未生成完整spec也可恢复；方案阶段保留已确认需求。开发/修复阶段恢复同一编辑检查点及暂存文件。审查阶段从已绑定的候选、源码摘要和工具结果索引恢复，源码未变时复用已经通过的仿真、Python和构建证据。

仅续接验证，不启动完整开发流程：

```powershell
.\.venv\Scripts\python.exe main.py verify <任务编号> --continue
```

该命令不能同时选择新 `--candidate`。普通 `verify` 表示重新验证；源码改变后，应重新验证而不是继续旧审查。已有的修复次数上限随阶段检查点保存，续接不会把只验证模式变为自动修复模式。

独立数据分析与资料研究分别使用原命令恢复：

```powershell
.\.venv\Scripts\python.exe main.py analyze <任务编号> --resume <分析会话ID>
.\.venv\Scripts\python.exe main.py board-research --board <板卡ID> --resume <资料任务编号>
```

用户可显式选择本次预算或思考强度：

```powershell
.\.venv\Scripts\python.exe main.py run --resume <任务编号> --continue --effort low
.\.venv\Scripts\python.exe main.py verify <任务编号> --continue --max-tokens <服务支持的输出上限>
```

这些选项只影响本次运行，不改写 `config.json`；服务是否接受所选预算以真实API结果为准。`--request` 仍表示修改整体需求，会使旧执行资格及待续接的验证阶段失效。

## 上下文和证据

- `model_steps/<阶段>-<标识>.json`：原阶段输入、模型草案、公开摘要、下一步、读取窗口、反馈和完成结果。
- `.feedback.txt`：较大接口反馈的全文；默认只传摘录，暂停后仍可读取。
- `editing/*.json`、`working.md`：文件编辑草稿和小步骤。
- `verification_checkpoint`：候选路径、源码摘要、当前审查/修复阶段、对应工具结果索引与修复上限。
- `revisions/`、`runs/`、`llm_calls.jsonl`：原候选、实际工具证据和API调用元数据。

审查默认传入项目元数据、文件索引和工具结果摘录，不再把全部源码与整份构建报告塞进首轮请求。完整文件与报告按需读取；`run`、`verify` 使用同一上下文组装方式。冻结需求不由框架随意压缩或删改。

旧版已经落成的需求、方案、文件交付和确认记录继续使用；新机制不会伪造旧版本缺失的阶段检查点。旧版在审查超限后直接报错的任务，如没有 `verification_checkpoint`，仍需先做一次普通 `verify`，之后的新暂停才能按阶段续接。已经启动的Python进程需要重新启动才能加载新代码。

## 本轮验证

38项回归测试通过，覆盖草案分轮合并、截断后恢复、原子更新、完整错误保留、需求无spec时恢复、中断恢复、规划确认保留、修复暂存恢复、审查不重跑工具、源码变化使旧证据失效、修复上限不扩大、显式预算覆盖、独立分析及资料研究超限等。

真实验证使用 `deepseek-flash / high / 32768`，新建8位奇偶校验纯仿真任务。DeepSeek生成工程并自行修复一次参考模型错误，真实XSIM的256个输入穷举及默认Python波形生成通过。随后在审查调用处**明确注入两次GenerationTruncated**，保存暂停并通过正常 `run --resume --continue` 路径恢复；真实DeepSeek继续读取文件并批准审查，最终 `simulation_verified`。

续接前后仿真次数都为2（首次参考模型错误、修复后通过），说明恢复审查未重跑工具；模型配置不变。本轮没有综合或下载。审查仍记录README缺少直接运行命令、负向故障注入分支仅静态检查等限制，没有把它们描述为已实际执行。

验证记录：[verification.json](../.validation/model-steps-live-1793429973306602900/verification.json)；任务产物位于其记录的 `task_dir`。故障注入是恢复测试，不能据此宣称真实模型永不超限。
